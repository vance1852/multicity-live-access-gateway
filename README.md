# 高峰出行查询的扇出网关与配额隔离

本目录提供现场联调用的合成合作方记录。记录中的机构、地点、旅客和标识均为虚构。每份记录可单独使用。

## 合作方报文

行程候选 `itineraries` 包含多个区段标识，`legs` 说明查询来源、实际收费键、查询范围和是否需要接驳证明。向来源请求使用 `GET /providers/{operator}/live/{query}`。同一键和范围、且面向兼容时段的查询结果可以共用；仅名称相似不意味着结果可共用。回报有 `covers`（现场实际可用时段）、`ttl_ms`（自本次返回起计的毫秒数）、`proof`（可为空，非空含承诺范围）。营运时段以当日分钟计，左闭右开。
`concurrent` 是上游物理处理中请求的数量上限，`credits` 是窗口中最多计入的调用成本，`desk_reserved` 给服务台保留；公众可用非保留部分。`charge` 是该请求一旦发出可能产生的成本。服务台身份由调用方在本地持有的接入资料提供，合成的客户端为 `public` 和 `desk`，没有真实服务凭据。客户端事件的 `at` 和等待时间以自演练开始的毫秒表示。

## 本地联调

使用 Python 3.11 的标准库。现场联调环境固定为 Python 3.11.2。启动本地资料端后保持该进程运行，默认只监听回环地址的 8090 端口。

```sh
python partner.py fixtures/shared-call-with-two-deadlines.json
```

资料端按路径回放记录中的响应。接口 `GET /fixture/facts` 返回起始事实，`GET /fixture/events` 返回按到达时间排列的原始事件。同一到达时刻的事件按记录中的顺序出现。`GET /fixture/journal` 返回收到的合作方请求，含未匹配及已收件但主动断开连接的请求。重启资料端会从该份记录开头开始。

`exchanges` 每条只使用一次，按方法、路径和列出的正文键值及请求头匹配最早尚未使用的记录。路径中的花括号匹配一个标识段。`delay_ms` 是合作方回包延迟，`drop` 表示合作方收到请求后直接关闭连接。未匹配的请求返回 404。记录字段可随新的联调资料调整。

在同一目录用 `python -m unittest -v` 核对资料载入和合作方接口，包括已记录的状态码、回包、断连及接收记录。
